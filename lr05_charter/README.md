# Статут проєкту

Студент: Герасимчук, herasymchuk-15. Тема: Planning poker з історією сесій, статистикою розкиду і експортом у трекер. Варіант вхідних умов: V09.

## 1. Навіщо цей проєкт

Проблема замовника: Кафедра щосеместру використовує сервіси Planning Poker під час навчання Agile, але безкоштовні рішення регулярно закриваються, змінюють умови використання або вимагають реєстрацію. Через це викладачі витрачають час на пошук альтернатив, а під час занять виникає ризик зриву сесії для групи до 25 осіб. Крім того, доступні безкоштовні сервіси не зберігають історію сесій та не надають статистику розкиду оцінок, яка потрібна для навчального аналізу.

Мета проєкту: Створити сервіс Planning Poker, який дозволяє проводити сесії без реєстрації, зберігати історію оцінювання, аналізувати розкид оцінок та експортувати результати у формат курсу.

## 2. Business case: чому саме це рішення

Порівнюються щонайменше два способи закрити ту саму проблему. Варіант «нічого
не робити» це теж повноцінний варіант зі своєю ціною.

| Варіант | Що це                               | Витрати                                   | Вигоди                                                                                    | Ризики                                                                |
| :-----: | ----------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
|    A    | Купити готовий платний сервіс       | 2 людино-тижні, 120000 грн підписок       | Швидкий запуск, мінімальна розробка                                                       | Залежність від постачальника, відсутність потрібного формату експорту |
|    B    | Розробити власну систему            | 44 людино-тижні, 0 грн зовнішніх ліцензій | Повний контроль над функціями, історія сесій, статистика розкиду, власний формат експорту | Ризики розробки і підтримки                                           |
|    C    | Використовувати безкоштовні сервіси | 1 людино-тиждень, 0 грн                   | Немає витрат на розробку                                                                  | Відсутність історії, ризик закриття сервісу, зміни умов використання  |

Звідки взялися числа:

| Число            | Звідки                                                                             |
| ---------------- | ---------------------------------------------------------------------------------- |
| 120000 грн       | Припущення: річна вартість командних підписок на комерційні сервіси Planning Poker |

Рекомендація: брати варіант B — власну розробку. Хоча він потребує найбільших трудовитрат, тільки цей варіант дозволяє реалізувати історію сесій, статистику розкиду оцінок і специфічний формат експорту, який потрібен замовнику. Альтернативи або не мають потрібних функцій, або створюють залежність від стороннього сервісу.

Що зміниться в рішенні, якщо бюджет вашого варіанта зменшити вдвічі: доведеться відмовитися від частини другорядних функцій, наприклад розширеної аналітики, але рішення залишиться власною розробкою. Купівля платного сервісу не забезпечить потрібні можливості навіть при меншому бюджеті.

## 3. Обсяг

Що робимо:

- Проведення сесій Planning Poker без реєстрації.
- Створення та керування сесіями оцінювання.
- Збереження історії сесій.
- Аналіз і візуалізація розкиду оцінок.
- Експорт результатів у формат курсу.
- Управління списком історій для оцінювання.

Чого не робимо в цьому проєкті:

- Не розробляємо мобільний застосунок, бо строк релізу становить лише 16 тижнів.
- Не інтегруємо систему з усіма популярними трекерами задач, бо це перевищує доступний бюджет.
- Не додаємо авторизацію через соціальні мережі, бо вона не потрібна для досягнення мети проєкту.
- Не реалізуємо відеоконференції всередині системи, бо для цього вже існують спеціалізовані сервіси.

## 5. Критерії успіху

Звідки цільові числа:
Для SC-01 число 25 учасників взято з контексту теми, де замовник прямо говорить про групу з 25 осіб.

Для SC-02 цільове значення 100% історій вибране тому, що статистика розкиду є ключовою вимогою замовника і має будуватися для всіх оцінених історій.

Для SC-03 цільове значення 100% успішних експортів обране тому, що невдалий експорт робить результат сесії непридатним для подальшого використання.

Критерій, за який буде найважче відзвітувати: SC-02, тому що необхідно не лише зберегти оцінки, а й правильно розрахувати та відобразити статистику розкиду для кожної історії.
